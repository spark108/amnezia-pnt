# PNT VPN

[English](README.md) · [Сервер PNT](https://github.com/spark108/pnt) · [Релизы](https://github.com/spark108/amnezia-pnt/releases/latest)

PNT VPN — VPN-клиент для Windows и Android на основе AmneziaVPN. Импортируйте выданный администратором профиль `.pnt`, нажмите «Подключить» и выберите разрешённый выходной сервер. PNT создаёт конфигурацию AmneziaWG на выбранном сервере и подключается напрямую либо передаёт VPN-трафик по маршруту PNT.

## Возможности

- Windows x64: графический клиент с отдельной фоновой VPN-службой; Android ARM64: системная VPN-служба Android.
- Однократный импорт профиля PNT. Выбор серверов обновляется перед подключением; изменение прав не требует нового импорта.
- Ограниченные клиентские идентичности: клиенты не участники кластера, не отображаются в топологии узлов, не передают транзитный трафик и не управляют PNT.
- Выходные AmneziaWG-серверы с нативной установкой на Debian или в Docker. Управление обычным WireGuard в PNT не поддерживается.
- В списке серверов — внешний IPv4 и задержка в `ms`.
- После подключения — внешний/внутренний IP устройства, рукопожатие, суммарный принятый/отправленный трафик, скорость, режим прямого/транспортного подключения и пинг до выхода/интернета.
- Раздельное туннелирование, замена реле с сохранением сеанса и обновление из релизов GitHub.

В сборке PNT убраны Premium/Free, установка серверов по SSH из клиента, обычный импорт VPN-ключей/файлов/QR, официальный бэкенд/сайт Amnezia и её проверка обновлений. Принимаются только профили доступа PNT.

## Установка и использование

Скачайте пакет из [GitHub Releases](https://github.com/spark108/amnezia-pnt/releases/latest).

**Windows:** распакуйте весь `PntVPN-windows-x64.zip`, выполните `install.ps1` в PowerShell администратора и запустите установленный `PntVPN.exe`. Служба и транспорт обязательны; одного GUI-файла недостаточно.

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

**Android:** установите `PntVPN-android-arm64.apk` на Android 10 или новее. При необходимости разрешите установку APK. При первом подключении подтвердите системный запрос VPN. Закрытие экрана не останавливает VPN-службу; для остановки нажмите «Отключить».

1. Получите `.pnt` у администратора кластера и импортируйте его один раз.
2. Нажмите «Подключить» и выберите выходной сервер. Показываются только разрешённые серверы.
3. После подключения статистика отображается в основном окне. Раздельное туннелирование и сброс профиля доступны при отключённом VPN.
4. Сброс профиля удаляет его локально, но не отзывает серверную идентичность и не сбрасывает привязку устройства. Сброс требует подтверждения.

Профиль содержит закрытую идентичность и доверенные сертификаты входных узлов PNT. Храните его как учётные данные. Привязка устройства дополняет защиту профиля, а не заменяет её.

## Привязка устройства

Новый профиль не привязан. Первое подключение закрепляет его за отдельным ключом Android Keystore или Windows CNG. Ключ устройства не входит в `.pnt`; после привязки импорт копии на другом устройстве не даёт доступ. До привязки профиль может занять тот, кто подключится первым.

Администратор управляет этим на участнике PNT:

```sh
pnt vpn client rename <client-id> NewName
pnt vpn client unbind <client-id>
pnt vpn client revoke <client-id>
```

`unbind` сбрасывает привязку, деавторизует текущую сессию и удаляет выданные AmneziaWG-ключи на доступных VPN-серверах. На отключённых удаление ожидает связи. Профиль может занять следующее устройство, включая прежнее. Для постоянного запрета используется `revoke`. Если при переустановке приложения/ОС потерян системный ключ, нужен `unbind`.

Узел, создавший клиента, последовательно принимает решения о привязке и должен быть доступен при авторизации; автоматического переноса управления нет. Для этого протокола обновите все участники PNT и клиентские приложения. Клиентам, созданным до привязки, нужен однократный `unbind`, назначающий управляющий узел и отзывающий старые сессии. Изменение подписанного содержимого, включая геолокацию узлов, делает подпись недействительной.

## Прямое подключение и реле

Сначала VPN-трафик идёт по UDP прямо к выходному серверу. PNT проверяет рукопожатие и использует маршрут, если прямое подключение не подтверждается. Управление и транспорт клиента до входа работают по TLS с закреплённым сертификатом через TCP 442. Между современными узлами PNT приоритетен QUIC через UDP 442, с резервом TCP.

Границы датаграмм сохраняются в надёжных потоках; QUIC DATAGRAM не используется. Активные и резервные реле проверяются heartbeat. При отказе реле транспорт может заменить его без пересоздания VPN-интерфейса и ключей. Возможна потеря пакетов; смена выходного сервера не сохраняет его NAT-сессии.

Пинг отображается как выход/интернет, например `100ms/103ms`; `—` означает отсутствие измерения. При прямом VPN-подключении это не внутренний пинг сети PNT. Правила раздельного туннелирования могут влиять на реальный путь измерений.

## Обновления и диагностика

Версия находится снизу по центру. Проверка обновлений выполняется фоном при запуске и периодически; нажатие на версию запускает ручную проверку. Новая версия показывается зелёным со стрелкой. Нажмите для загрузки и установки после проверки размера/SHA-256. Windows запросит права администратора; Android откроет системный установщик. Перед установкой VPN отключается. Для сохранения данных Android нужны прежние application ID и совместимая подпись.

Файлы релиза должны называться `PntVPN-windows-x64.zip` и `PntVPN-android-arm64.apk`; контрольные суммы находятся в `SHA256SUMS.txt`. Замена файла без изменения версии не вызывает автоматическое предложение обновления: в таком случае APK нужно скачать и установить повторно вручную.

При ошибке импорта используйте последний Android APK: замена в релизе 5.1.0.9 исправляет проверку профилей с геолокацией, дробными координатами и null, сохраняя старые профили. Не редактируйте подписанный файл. При отказе привязки обратитесь к администратору вместо изменения конфигурации.

Для диагностики Android используйте `adb logcat`, фильтры `PntTransport`, `PntVPN` и `AndroidRuntime`. Не публикуйте полные профили и закрытые ключи вместе с журналами. Серверные журналы и команды описаны в [репозитории PNT](https://github.com/spark108/pnt).

## Сборка из исходников

Инициализируйте подмодули:

```sh
git submodule update --init --recursive
```

Нужны CMake, Ninja, Conan 2, Qt 6.10+ и инструменты целевой платформы. Для Windows — MSVC, .NET 10 SDK и исходники PNT для сборки транспорта. Для Android — JDK 17, Android SDK, NDK r27c, Qt для Android ARM64 и соответствующие Qt-инструменты настольного хоста. Замените `<...>` в примерах своими путями.

```sh
# Windows, в окружении MSVC:
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DPNT_CLIENT_ONLY=ON -DPNT_SOURCE_DIR=<pnt-source> -DCMAKE_PREFIX_PATH=<Qt-desktop>
cmake --build build --parallel
```

```sh
# Android:
cmake -S . -B build-android -G Ninja -DCMAKE_BUILD_TYPE=Release -DPNT_CLIENT_ONLY=ON -DCMAKE_TOOLCHAIN_FILE=<Qt-Android>/lib/cmake/Qt6/qt.toolchain.cmake -DQT_HOST_PATH=<Qt-host> -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-29
cmake --build build-android --target PntVPN_prepare_apk_dir --parallel
```

Используйте сгенерированные deployment settings с `androiddeployqt`, чтобы подготовить полный манифест, ресурсы и нативные библиотеки, затем собирайте OSS-вариант Gradle. Убедитесь, что в пакет попала новая `libPntVPN_arm64-v8a.so`. Для релиза нужны постоянный ключ подписи и история его ротации. Не храните ключи/пароли в репозитории.

Android-тесты запускаются через `testOssDebugUnitTest`. `PNT_TEST_PROFILE` может указывать на временный тестовый профиль вне репозитория для проверки совместимости подписей/идентичностей .NET. Фикстуры геолокации содержат только публичные тестовые сертификаты. Дополнительные проверки находятся в `client/tests/`. Для нового релиза повышайте `PNT_VERSION` и Android version code PNT.
